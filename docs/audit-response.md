# Audit response

Each finding from the v2 design audit, what the code does about it, and the tests that show it. Since 2 Nov 2026
the contract is the lean **v2** (docs/decisions.md D-28): the same guarantees for custody, destinations, budgets,
invoices, the cooldown and the executor, with the ledger, reconciliation and term hashes moved off-chain. Rows say
where a defence changed. v1 and its tests are at git tag `v1-full-contract`.

Test paths are relative to `contract/src/` unless they start with a package. Run them with `cd contract && cargo test`
(47 tests), `cargo test --test sandbox -- --ignored` (the real wasm on a local node), `pnpm test`,
`pnpm test:sandbox` (`devkit/test/`) and `pnpm demo:mock` (every fixture through the whole pipeline).

## What the random walks check after every step

`tests/props.rs` (`contract_invariants_hold`, 16 walks by default, 200 checked on 2 Nov), over arbitrary
interleavings of proposals, owner decisions, attempts, re-quotes, funding, delivered and stale callbacks, time
jumps across days, supplier changes, pauses, rotations, withdrawals and forgetting:

- Each step sends at most one payout, to exactly the payee it must: a native supplier's recipient at the intent's
  revision, or the attempt's deposit; anything else sent without a callback goes only to the owner (withdrawals).
- Per UTC day: everything sent ≤ `daily_cap`; approved by the agent alone ≤ `autonomous_daily_budget`; funded from
  the trust budget ≤ `executor_trust_daily_budget`; today's on-chain counter equals what was sent today.
- An intent is paid at most once plus the number of owner retries.
- `paying` equals the number of `PAYING` intents; `stored_intents` equals the number stored, never above 50.
- Callbacks never panic, and a stale callback changes nothing.
- `random_walks_reach_deep_states` checks the walks actually reach native and cross-chain payouts, owner-signed and
  trust funding, re-quotes, failures, retries, settling after the grace time, stale callbacks, the cooldown and
  forgetting.
